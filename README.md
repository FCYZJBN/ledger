# 记账本 📒

> 跑在手机浏览器里的**本地记账 App**：单式记账、收支都记、两级分类、预算红线、图表报表。数据全部存在本机（IndexedDB），**不上传任何服务器**。

**在线使用**：<https://fcyzjbn.github.io/ledger/>

---

## 📱 手机上 3 步装好

1. 手机浏览器打开 <https://fcyzjbn.github.io/ledger/>
2. 右上角菜单 → **「添加到主屏幕」**（Chrome/Edge 都支持）
3. 桌面点开「记账本」图标，即可像 App 一样**全屏、离线**使用

> 离线能力由 Service Worker 提供（已注册并缓存全部静态资源），冒烟测试里有两条断言钉着：一条验 SW 注册、接管与缓存完整性，一条**清空 HTTP 缓存后断网重载**验证真能打开 —— 不清缓存的话普通 HTTP 缓存会造成「离线可用」的假象。

## ✨ 功能

- **记一笔**：3 秒完成，默认今天日期、大金额键盘、常用分类、账户标签、选填备注。
- **两级分类**：预置 9 大支出类 + 5 大收入类及常用子类；图标一键点选、颜色、归属都可自定义。
- **账户标签**：微信 / 支付宝 / 现金 / 银行卡 / 信用卡，可自定义。
- **预算红线**：设每月总支出上限，用掉 80% 进度条变黄、超支变红（只提醒、不拦截）。
- **分类预算**：可给餐饮、居住等单个支出大类单独设预算，只设你在意的几个；记账刚好花超时当场轻提示，不打断记账。
- **总预算 ↔ 分类预算联动**：两边对不上时保存会问你「把总预算改成分类合计」还是「保持总额、差额记为未分配」，不替你决定。首页分类预算卡显示未分配额度，**未设预算的分类每花一笔就从里面扣**。
- **统计报表**：本月 / 上月 / 近 3 月 / 今年 / 全部 的收支结余、日均支出、分类占比环形图、支出趋势柱状图。
- **退款**：记成**负数支出**（记一笔时勾「这是一笔退款」），把钱从该分类的支出里扣回去。它**不是收入** —— 记成收入会让本月支出和收入同时虚高，还白白吃掉分类预算。
- **明细**：按日期分组，支持类型 / 分类 / 账户 / 月份筛选，可编辑、复制、删除。
- **离线可用**：添加到主屏后断网也能照常记账、看报表（Service Worker 缓存全部静态资源）。
- **账单导入**：把微信、支付宝导出的账单文件丢进来，自动解析、自动归类，逐行确认后批量入账，可整批撤销。**文件只在浏览器本地解析，不上传。**
- **数据安全**：JSON 全量备份与恢复、CSV 明细导出（Excel 可直接打开）。

## 📖 使用说明

- **记一笔**：点底部 ➕，输入金额 → 选分类 → 选账户 → 保存（日期默认今天，可改）。
- **分类与账户**：设置 → 分类管理 / 账户管理，可增删改；大类下还能建子类，图标点选、也可自定义 emoji。
- **预算**：设置 → 每月支出预算帽，保存后首页显示进度条。
- **分类预算**：设置 → 分类预算，给支出大类逐个填金额（留空=不设），保存后首页出现「分类预算」卡，按超支程度排序。
- **总预算与分类预算的关系**：`总预算 = 各分类预算合计 + 未分配`。两边对不上时保存会提示你选哪边对齐——选「把总预算改为分类合计」就直接同步，选「保持总额、差额记为未分配」则差额留在未分配里，**未设预算的分类花钱会从里面扣**，扣光了未分配会标红。调低总预算到已分配金额以下同样只提醒、不拦截。
- **导入账单**：设置 → 导入账单（微信 / 支付宝）→ 选文件 → 待确认页逐行过一遍 → 确认导入。
  - **微信**：我 → 服务 → 钱包 → 账单 → 常见问题 → 下载账单 → 用于个人对账，选时间范围、填邮箱收文件。收到的是**加密压缩包**，需先解压出内部的 `.xlsx` 再导入（浏览器无法解 AES 加密包）。
  - **支付宝**：我的 → 账单 → 右上角 ⋯ → 开具交易流水证明 → 用于个人对账，选时间范围、填邮箱收文件。收到的是 `.csv`，直接导入。支付宝导出为 **GBK 编码**，App 会自动识别。
  - **对账硬闸门**：解析出的条数与收支合计必须和账单自带的汇总**完全一致**，对不上直接拒绝导入 —— 格式变了宁可报错，也不让错账进来。
  - **重复导入安全**：每笔带账单交易单号，同一份再导一次全部标「已导入」；日期+金额+方向撞上手记记录的标「疑似重复」且默认不勾选（用组内配额抵消，不会误伤账单里真实的同日同金额多笔）。
  - **归类**：支付宝按自带交易分类映射；微信按商户关键词规则猜。你改过的商户会记进本地规则，下次优先按你的选择走。
  - **退款自动转换成负数支出**：账单里退款是「收入」那行，导入时会转成负数支出，从支出里扣掉。同一次退款并存的原始消费行保持正常支出（那笔钱当时确实花出去了），两者相抵净额为 0。因为账单自带的汇总把退款算作收入，**对账仍按账单口径**，转换发生在对账之后。
  - **撤销**：确认导入后结果块提供「撤销本次导入」，整批一次退回。
- **备份与恢复**：设置 → 导出备份（JSON）下载文件；换手机或清理浏览器数据前务必先备份，再到新设备导入即可恢复。

## 🔌 离线与版本更新

Service Worker 采用 **cache-first**：打开时立刻用本地缓存渲染（秒开、断网也能用），同时在后台悄悄拉一份新版存起来。

- **代价**：刚发布的新版要**第二次打开**才生效。第一次打开看到的仍是上一版，这是为「秒开 + 稳定离线」付的价。
- **对开发者的约束**：改了任何被缓存的资源（`js/*`、`css/*`、`index.html`、图标等），**必须同时把 `sw.js` 里的 `CACHE` 版本号 +1**。策略是 cache-first，不升版的话老用户会一直命中旧缓存，永远看不到新功能。（版本号是多少去 `sw.js` 里看 —— 这里不写死，免得又过期。）
- `sw.js` 里的 `ASSETS` 用的是 `caches.addAll()`，**全或无**：任一资源路径写错就整批失败，SW 装不上、离线能力全无。所以新增文件必须同时加进 `ASSETS`。
- 这条有测试兜着：`离线·SW 注册并接管` 会断言缓存条目数与非空，`addAll` 整批失败会当场暴露。

## 🔒 数据安全

- 数据存在**本机浏览器**（IndexedDB），无账号、无云端、无追踪。
- **导入的账单文件全程本地解析，不发起任何网络请求** —— 这条不是口号，冒烟测试会开着 CDP 的 Network 域统计全程请求，断言除页面自身资源外零出站（`账单·全程零出站请求`）。
- 仓库 `.gitignore` 屏蔽了 `*账单*` / `*交易明细*` / `*.xlsx` 等通配，防止真实账单被误提交（本仓库是公开仓库）。
- 清理浏览器数据会清空记账，请定期用「设置 → 导出备份（JSON）」保存到网盘 / 电脑作为唯一安全网。

## ⚠️ 账单导入的限制

- **是批量导入，不是实时记账。** 得你主动导出账单再导进来；纯静态 PWA 没有后台进程，拿不到微信 / 支付宝的扣款通知（那需要原生 Android 的通知读取权限）。
- **微信那一步解压躲不掉。** 微信发来的是 AES 加密压缩包，浏览器做不了这个解密，得先解压出 `.xlsx`。
- **账户整批统一。** 一次导入共用一个账户，不按账单里的「零钱 / 余额宝 / 银行卡」细分。
- **内部资金挪动默认不计。** 支付宝「账户存取」（小荷包自动攒）、微信「零钱提现」是左口袋进右口袋，默认不勾选。
- **退款会自动转成负数支出。** 账单里退款是「收入」那行，导入时转成负数支出从支出里扣掉，不打进收入。原始消费行保留，两者相抵净额为 0。
- **微信归类靠关键词猜**，人不认识的个人收款码无法自动归类，需手动选一次（选过之后会记住）。

## 🛠 面向开发者

纯原生实现，无构建步骤：**JS ES Module**（无框架）+ **IndexedDB**（本地存储）+ **ECharts**（图表，本地打包）+ **PWA**（Service Worker + manifest，可离线）。

### 本地运行

本项目使用 ES Module，需通过 http 服务（并保证 `.js` 返回正确 MIME）：

```bash
node scripts/serve.js        # 默认 http://localhost:8000
# 或
npx serve .
```

> 注意：`file://` 直接打开可正常记账，但「添加到主屏 + 离线」需要 https/localhost。Windows 上 `python -m http.server` 会把 `.js` 当 `text/plain` 返回，导致 ES 模块加载失败，不建议用它测试本项目。

### 部署到 GitHub Pages

1. 新建 GitHub 仓库，推送本目录。
2. 仓库 `Settings → Pages`，Source 选 `main` 分支根目录，保存。
3. 得到网址如 `https://你的用户名.github.io/仓库名/`。
4. 手机 Chrome/Edge 打开该网址 → 菜单 →「添加到主屏幕」。

### 国内网络推送备用方案

若 `git push` 连不上 github.com（`api.github.com` 通常仍可达），可用 Git Data API 兜底推送：

```bash
node scripts/deploy.mjs
```

它会读取当前 HEAD 的提交信息，把本地文件全量同步成一个提交推到 `main`。注意提交由 GitHub 侧生成，**本地与远端内容一致但 sha 不同**；等 github.com 恢复后执行 `git fetch origin && git reset --hard origin/main` 对齐即可。
